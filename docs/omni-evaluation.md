# Omni 语音模型选型（2026-11-15）

原生 Omni 语音链路已在 OpenI 实测：MiniCPM-o 4.5 接收音频并生成文字和语音，同机和媒体服务器转发各三轮成功。有效首音 p50 分别为 **1722.7 ms、1837.4 ms，未达到一秒目标**。这是单路、预热后的合成问题与内存播放测量；正式电话/WebRTC、打断和挂断工具尚未接入这条实验链路。现有三模型 provider 和配置继续保留。

## 候选与硬件

| 候选 | 已核实能力 | 对现有 A100 40GB 的判断 |
| --- | --- | --- |
| MiniCPM-o 4.5，9B 总参数 | 中英语音、可配置提示词和参考音色；流式音频输入/输出、全双工；官方提供 PyTorch 和 llama.cpp-omni 服务示例 | 已在 A100 40GB 测得六轮半双工语音，结果见下文。官方完整 PyTorch 服务要求至少 28GB 显存；本次关闭视觉、仅测单路语音的已分配显存与该门槛不是同一口径 |
| Qwen2.5-Omni-3B | 音频输入、文字和语音输出；Thinker–Talker 架构 | 可作较小模型对照。官方 BF16 表的 18.38/22.43/28.22GB 对应 15/30/60 秒**视频**输入、FlashAttention 2 的理论下限，不能直接当作电话显存实测 |
| Qwen3-Omni-30B-A3B-Instruct | 音频输入、流式文字/语音输出；MoE | 不作为本轮省费首选。激活 3B 不代表只加载 3B；完整模型为 30B，官方 BF16 15 秒视频示例理论下限为 78.85GB。量化及其他引擎需分别验证，不能据此断言所有路径都无法在 40GB 运行 |

MiniCPM-o 4.5 的量化 llama.cpp-omni 路径，官方列出的 NVIDIA 门槛为 12GB 显存；不等于所有量化格式、上下文和并发都只用 12GB。先在已经验证可用的 A100 上测无损路径，达标后再用同一组问题对照低价显卡或量化，避免同时改变模型、引擎和硬件。

## 为什么优先核查真实流式服务

Omni 内部仍可能包含文字解码、语音 token 解码和声码器；参数较少、减少 HTTP 请求或模型宣称流式，都不保证停口后一秒内出声。

MiniCPM 官方 PyTorch 服务表中的 A100 全双工每单元约 0.9 秒、启用编译约 0.5 秒是**官方单元耗时**，不是本项目的停口到终端有效首音。该表还记录编译准备成本，不能隐藏首次编译、预热和实际网络开销。其模型评测中的 0.6 秒首 token 也不是首段有效语音。

Qwen2.5-Omni 官方说明普通 `vllm serve` 路径只支持 Thinker 的文字输出；语音需要专门的端到端实现，不能把标准 Chat Completions 接口配置好就称为可说话。语音输出还要求特定系统提示词；官方将角色定制放进预置对话的方案，需检查产品约束、金额、销售步骤和挂断要求能否稳定遵循。

MiniCPM-o 官方也列出全双工下可能读错字、混用中英文和能力不稳定的限制。对电话咨询，必须另测价格、车型/产品型号、地址和拒绝购买等具体语义。

## 实验边界与待验项目

1. 先确认 OpenI 可挂载的完整权重或准备好经验证的镜像；锁定模型、远程代码和依赖版本。准备完成后才占用 GPU 做少量推理，语音组件采用国内镜像、断点续传和进度日志，允许最多两小时准备，避免短时限导致反复停止重建。
2. 复用现有测试问题和虚构产品资料，关闭思考；记录从用户讲话期间的分块输入、真实停口边界，到首段有效中文语音的全过程。完整输入一次提交、首 token、PCM 首包分别记录，不混成端到端结果。
3. 先测单路已预热的原生流式语音，再测媒体服务器转发。分别报告初始化、预热、首文字、首 PCM、前导静音、有效首音与音频持续时长；少量样本不做稳定性承诺。
4. 对连续打断隔离生成代次，旧语音和工具结果不能恢复播放。已播放内容、被打断的背景、最新用户问题继续区分，不能直接用模型完整生成稿覆盖正式历史。
5. 销售和咨询提示词、一次挽留、明确结束、告别播放后挂断都须回归。全双工模型决定发声，不等于获得自行挂断授权；原有播放屏障和工具校验继续生效。

独立 MiniCPM-o 4.5 原生半双工流式实验的源码、依赖和语音资产锁定方式见[实验说明](../experiments/openi_latency/README.md#omni-独立实验)。实际六轮结果见[脱敏 JSON](../experiments/openi_latency/results/2026-11-15-omni.json)，未修改正式服务。三模型优化和 DeepSeek 对照结果见[响应速度文档](latency.md)及[实验记录](../experiments/openi_latency/README.md)。

准备阶段已完成站内主权重加载、五个语音资产校验和独立依赖安装。首次参考音色缓存初始化遇到上游 FP32 输入与 FP16 权重不匹配，已定位到 minicpmo-utils 1.0.5 的缓存路径缺少 autocast；适配层补齐初始化精度上下文。缓存镜像已提交成功，任务 935021 复用完整语音组件和依赖，重新绑定站内主权重后初始化成功；前一次准备失败不计为推理样本。

## 2026-11-15 实测

任务 935021 使用 `voice-omni-assets-20261115` 镜像、独立仓库提交 `7c20dc7242`，实际 GPU 为 A100 PCIe 40GB。Torch/Torchaudio 2.6.0、CUDA 12.4、Transformers 4.51.0、minicpmo-utils 1.0.5；主模型 BF16、SDPA，Token2wav FP16，关闭思考与视觉。模型及音色缓存初始化 31.37 秒，初始已分配显存约 18.77 GiB，截至六轮结束累计观测峰值已分配约 19.50 GiB；不等于整个进程显存或其他显卡的容量承诺。

下表为停口到内存播放队列首段有效语音，单位 ms，包含 200 ms 模拟停口等待。功能、价格、试用均为虚构测试产品资料。

| 问题 | OpenI 同机 | 媒体服务器转发 |
| --- | ---: | ---: |
| 它可以做什么？ | 1742.4 | 1861.0 |
| 订阅多少钱？ | 1567.1 | 1682.0 |
| 可以先试用吗？ | 1722.7 | 1837.4 |
| 本组 p50 | 1722.7 | 1837.4 |
| 本组三轮最大值 | 1742.4 | 1861.0 |

六轮回复文字均回答了相应问题：整理文档、总结会议和辅助写作；每月 99 元；支持先试用再订阅。模型直接理解音频，没有独立 ASR 转写；问题由同一模型强制朗读生成，存在合成输入偏差，不能据此评价真实来电识别率或听感。

最终音频预填约 73.4～78.4 ms，收到结束信号后首 PCM 约 1085.8～1261.1 ms；文字也在这一语音块交付，并非内部首 token。输出另有约 260～280 ms 前导低幅度片段，模拟停口等待和传输再计入终端有效首音。尾块补零 540～780 ms 仅是模型输入补齐，不按这一时长实际等待，不能直接从延迟中减掉。

此前三模型分块复位后的完整链路 p50 为同机 2456.0 ms、转发 2812.6 ms。本次 Omni 数值更低，但两次运行的合成波形和生成内容不同，仅作选型参考，不是只改变模型的严格 A/B。下一步应优先拆测原生语音块生成与声码器，再对照官方编译/推理引擎；缩短停口等待不足以消除本次超过一秒的首 PCM。全双工、量化或加速引擎均未由本次结果验证。

任务运行时间为 2026-11-15 16:57:05～17:01:35（Asia/Shanghai），平台已确认 `STOPPED`，270 秒按 9 积分/小时估算 **0.675 积分**，非官方账单。媒体服务器临时客户端、令牌目录和本机临时 SSH 密码文件已删除并核对；正式服务未修改或重启。仅六个样本，未验收稳定 p95、真实 VAD、电话、浏览器设备、回声、连续打断、并发、长上下文及完整业务提示词/挂断工具。
