# 低延迟语音实施方案（2026-11-15，独立实测完成）

2026-11-17 更新：[管线优化与同体量音色克隆选型](pipeline-optimization.md)记录真实网页基线、本地代码改动及未部署边界。最新浏览器测试尚未达 1 秒；不沿用旧实验结果作为当前终端验收。

目标是用户停口至第一段有效回复语音不超过1000ms，并让后续语音持续供给。首PCM、首文字、填充话和静音不能替代有效回复。最终结论需以逐轮完整链路与播放队列记录更新。

## 当前架构

自有服务器负责网页/电话入口、音频收发、播放队列和会话控制；OpenI同一GPU常驻识别、文本与合成模型。保留旧咨询/销售及供应商能力；2026-11-15按最新授权备份后将正式服务器三组模型API切到OpenI常驻服务。独立实验与正式HTTP接入结果分别报告。单通道预热实验先使用A10040GB，不能将它的结果当作低规格GPU或并发性能。

## 为什么不直接使用Omni小块版

Omni同机逐项首音1698.6→1471.4→917.0→820.4ms，分别对应真实裁静音、块8/文字3及100ms模拟端点；媒体转发6次890.2ms中位数、920.0ms最大。但每条回复累计供音空档927.0～2190.6ms，无法满足连续播放。继续缩小到块5反而变慢。默认Inductor和此前reduce-overhead均未获得成功的编译延迟样本。

Qwen3-TTS Graph4固定完整文本单项中位数306.2ms、最大330.5ms，比先前CosyVoice复位分块单项1645.7ms更有希望；两轮不是严格A/B，不能相减当作当前完整链路收益。

## 业务与取消

生产接入时保留生成代次与会话快照。用户开口后先停止终端播放并清空队列，再取消文本/TTS任务；每段迟到PCM校验代次后才能发送。新用户问题决定当前回复，未播放生成稿不能当成已说内容。保留明确结束工具校验、一次挽留、告别完整播放后挂断。

本轮实验复用隔离原型的取消和代次过滤，只验证独立链路；不宣称已接入并验收上述生产业务。代码具备取消丢弃迟到PCM的轻量回归。

## 验收与下一步

先测同机、再经媒体服务器转发相同合成问题，记录停口至有效首音、ASR final、LLM首文字、首PCM、整个生成耗时、音频时长、首音后队列空档及失败。模型加载与算子预热单列；费用包括准备、失败和误启动，GPU结束后核实STOPPED。

若SenseVoice整句模式完整链路足够快，先保留这条简单路径；若识别或停口确认成为瓶颈，再对照Paraformer在线模型，用户讲话期间执行增量识别，结束时只flush尾块。不能仅将SenseVoice的streaming开关设true冒充在线模型。流式识别需校验final归属当前代次、缓存独立、短停顿与连续插话。

最终发布前仍需真实VAD、麦克风/电话、回声、价格型号准确性、多轮业务提示词与音质验收。不得靠增加首播缓冲隐藏总时延；也不能只保证第一包而放任后续断粮。当前无真实线路稳定性承诺。

## 完整链路结果与最终选择

Graph4组合同机三轮首音998.8/747.8/1017.7ms，2/3低于1秒；媒体服务器六轮1019.2/866.1/1044.7/912.8/809.3/997.6ms，4/6低于1秒。nearest-rank p50为912.8ms，常规定义中位数955.2ms，最大1044.7ms；此前报告的p50同样使用nearest-rank，偶数样本不应混称常规中位数。本轮全部九条队列断粮为0，媒体回复音频1.76～7.68秒，生成1.12～3.74秒。只证明这些输入的供音足够，不能推导真实电话无停顿。

优先选择三模型Graph4服务，Omni小块版保留实验入口。当前仍有超1秒样本，尚未完成严格1秒验收；下一项优化应测短首句与真正在线识别，而非降低计时口径。模型加载/预热49.82秒，未计入逐轮。媒体RTT65.0ms，不能视为全部网络损耗，也不能从异轮首音差直接扣除。识别最终计算约72～77ms，首LLM文本从结束消息起约123～133ms，说明当前长首句准备和TTS首音仍是重点。

上述实验任务935201于21:10:55～21:17:55运行420秒，已核实STOPPED；误启动935197运行39秒也已STOPPED，两项估算1.1475积分，非账单。前优化批14.700积分另列，合计15.8475积分不包括更早选型和之后常驻服务。完整数据见[逐轮JSON](../experiments/openi_latency/results/2026-11-15-hybrid.json)。

用户随后明确要求持续提供服务并切换服务器API，因此后续常驻任务保留运行，不再沿用“测完即停”。常驻接口、配置和上线验证见[服务说明](openi-model-service.md)。本轮性能数据仍属于独立原型，不能冒充正式网页/电话验收。


## 常驻接入后的业务结果

旧任务935216已被新版935254替换。此前服务器103.52.153.233已保存三组兼容API配置。真实接口与取消测试通过，但使用原业务提示词、600ms端点和HTTP三接口的单轮内存终端首段有效语音为 **3879.2ms**，未达到1秒；该结果优先于任何对独立实验的线上外推。服务器仍承担原通话编排，因此尚未实现实验中的全部同GPU内存衔接收益。当前交付是常驻模型服务及可用接入，严格1秒验收仍未完成。详细分项、备份位置及证据见[上线记录](openi-model-service.md#2026-11-15-旧-http-链路上线记录)。

## GPU 整条业务管线（新版）

`voice.pipeline=gpu` 把原 Pipecat 业务管线移到常驻 GPU 进程：16kHz 单声道 PCM 经一条鉴权 WebSocket 进入，VAD、ASR、上下文、LLM、分句与 TTS 在 GPU 端衔接。三模型直接调用内存适配层，不再经业务服务器分别发起 HTTP 请求。业务服务器保留网页/电话入口、输出队列与历史落库。`local` 保留原独立 API 编排，不自动故障回退。

配置页的“处理链路”可切换；GPU 模式使用文本模型根地址推导 `/realtime`，使用文本模型密钥鉴权。远端 `serve_realtime=true`，三模型名、24kHz PCM 和参考音色必须与服务匹配。新增 `requirements-realtime.lock` 固定 Pipecat 运行依赖，复用镜像模型栈，不下载新的 Torch/CUDA。快照去除全部模型密钥及电话线路凭据；GPU 不保存音频和对话。

GPU 按生成代次标注音频；插话后发出 flush，服务器清播放队列并丢弃过期音频。句子提交和挂断必须等服务器输出队列的 played 确认，过期确认不能恢复旧回复或执行挂断。保留现有咨询、销售、一次挽留和告别规则。单个 GPU 服务只允许一通实时会话，重复占用明确失败，断连释放任务和占用。

停口确认现在支持100ms，较短阈值可能拆开自然停顿，需要真实麦克风/电话验证。响应目标仍按停口到终端有效声音计时；不能将独立原型数据作为新版正式链路数据。业务服务器与 OpenI 模型服务器分别更新；当前账号只允许一个 GPU 在线任务，更新 GPU 时需安排模型加载中断窗口。常驻服务不自动到期关闭。
