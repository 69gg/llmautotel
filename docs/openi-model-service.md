## 启动与资源

使用 `experiments/openi_latency/settings.service.json` 模板，复制为实验私库的 `settings.run.json`，只填强随机 API 令牌的 SHA256，原令牌保存在服务器受限权限配置中。模板不含供应商凭据。`serve_models=true` 时启动器复用已验证的镜像、权重校验、ASR 隔离进程和依赖锁，直接启动常驻模型 HTTP 服务；不经过实验的两小时客户端窗口、70轮预算或自动测试循环。模型加载、warmup 完成才开放端口，不将准备过程当成 ready。

## API 与配置

所有模型接口使用 `Authorization: Bearer ...`，仅 `/health` 无需鉴权；不保存录音、PCM、对话日志或原始密钥，不启用访问日志。请求体最多8MiB，ASR最多120秒，LLM输入上限16384 token、单次生成768 token/30秒，TTS每次最多2000字。上限是独立配置，不回写业务资料。

| 角色 | 接口 | 模型与参数 |
| --- | --- | --- |
| ASR | POST `/v1/audio/transcriptions` | multipart `model=FunAudioLLM/SenseVoiceSmall`，`file`为16kHz单声道16bit WAV，返回`text`；整句识别 |
| LLM | POST `/v1/chat/completions` | `model=Qwen/Qwen3-1.7B`；SSE或完整JSON，关闭思考，完整接收服务器消息与函数工具 |
| TTS | POST `/v1/audio/speech` | `model=Qwen/Qwen3-TTS-12Hz-0.6B-Base`，`voice=reference`，`response_format=pcm`，24kHz单声道16bitLE流 |

服务器三组根地址均填 `https://<实际OpenI代理>/v1`，ASR/TTS协议选兼容OpenAI。TTS仅当前镜像公开参考音色，不声称支持任意音色或风格指令；旧MiMo专属语气字段需要在切换配置时清空。默认没有暴露任意模型下载、代码执行、令牌回读或重启接口。

Qwen工具标签按任意文本块边界解析为标准`delta.tool_calls`，不将工具JSON播报；名称必须属于请求提供的工具，参数必须是对象，标签缺失或不完整会失败。挂断、证据及挽留校验复用原业务代码：GPU 模式在 GPU 执行，local 模式在业务服务器执行。小模型支持工具协议不代表业务准确性已验收。

ASR、LLM、TTS分别加锁，允许LLM继续生成时TTS合成已完成小句；不将三个接口串进一个全局锁。每个流独立取消标记与有界队列，HTTP断连后丢弃旧结果，旧生成退出前不复用相同模型；TTS每句PCM实际流式返回。服务关闭时释放ASR子进程。未知模型、音色、格式明确拒绝，不能静默换用其他模型。

`service_tts_first_audio_priority=true` 可让 TTS 每段首个非空 PCM 产生前，暂停 LLM 后续 token 解码，减少同卡争用；首块交付前即释放，后续继续并行。未配置时保留旧并发行为。取消、空输出和异常同样释放，等待受原请求截止时间约束。这不是 CUDA 硬抢占，也不保证一定降低延迟，需以重启后的正式链路测量为准。参考音色缓存、CUDA Graph 和 chunk4 已在原版本启用，不属于本次新增收益。

首段分句增加中文顿号边界，保留数字、ASCII 型号列表；不任意截断字数。通用提示要求先用短句给有效答案，以句号结束，再补充内容，适用于咨询和销售，不按具体产品硬编码。

## GPU 整条业务管线（新版）

`voice.pipeline=gpu` 把原 Pipecat 业务管线移到常驻 GPU 进程：16kHz 单声道 PCM 经一条鉴权 WebSocket 进入，VAD、ASR、上下文、LLM、分句与 TTS 在 GPU 端衔接。三模型直接调用内存适配层，不再经业务服务器分别发起 HTTP 请求。业务服务器保留网页/电话入口、输出队列与历史落库。`local` 保留原独立 API 编排，不自动故障回退。

配置页的“处理链路”可切换；GPU 模式使用文本模型根地址推导 `/realtime`，使用文本模型密钥鉴权。远端 `serve_realtime=true`，三模型名、24kHz PCM 和参考音色必须与服务匹配。新增 `requirements-realtime.lock` 固定 Pipecat 运行依赖，复用镜像模型栈，不下载新的 Torch/CUDA。快照去除全部模型密钥及电话线路凭据；GPU 不保存音频和对话。

GPU 按生成代次标注音频；插话后发出 flush，服务器清播放队列并丢弃过期音频。句子提交和挂断必须等服务器输出队列的 played 确认，过期确认不能恢复旧回复或执行挂断。保留现有咨询、销售、一次挽留和告别规则。单个 GPU 服务只允许一通实时会话，重复占用明确失败，断连释放任务和占用。

停口确认现在支持100ms，较短阈值可能拆开自然停顿，需要真实麦克风/电话验证。响应目标仍按停口到终端有效声音计时；不能将独立原型数据作为新版正式链路数据。业务服务器与 OpenI 模型服务器分别更新；当前账号只允许一个 GPU 在线任务，更新 GPU 时需安排模型加载中断窗口。常驻服务不自动到期关闭。
