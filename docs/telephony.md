# 电话接听与外呼 provider

电话接入与网页语音共用可选的咨询／销售模式、配置快照和单会话限制。工作台默认展示来电接听；原销售外呼保留。四组 provider 总开关和接听开关全部默认关闭，未启用时不连接或拨号。显式启用接听后维护原生入呼事件连接，或接受云平台认证回调；只有手动提交被叫号码才开始外呼。优先入呼步骤见 [来电接入](telephony-inbound.md)。

| Provider | 模式 | 适用线路与设备 | 前置条件 |
| --- | --- | --- | --- |
| Asterisk | 自带语音模型 | 运营商 SIP 中继、通过 SIP 接入的 FXO／E1／VoLTE SIM 网关 | ARI、原生双向 WebSocket 媒体、PJSIP 线路 |
| FreeSWITCH | 自带语音模型 | 运营商 SIP 中继、通过 SIP 接入的 FXO／E1／VoLTE SIM 网关 | ESL、原生 UDP unicast、SIP gateway |
| 阿里 AICCS 通信智能引擎 | 平台托管语音 | 大模型应用绑定的呼入号码或外呼线路 | 云应用、正式呼入变量回调／外呼接口、LLM 网关与回执 |
| 腾讯云客服 TCCC | 平台托管语音 | 来电 AI 智能体或平台外呼线路 | 正式动态来电路由／外呼接口、自有 LLM 网关与回执 |

硬件的模拟／数字／蜂窝接口由网关转换成 SIP，应用在 PBX 层接入，避免按品牌重复实现同一协议。SIM 网关必须支持甲方所选运营商的 VoLTE 语音和线路规则；只有数据连接的 4G 模块不能据此当作语音网关。设备型号、号码和中继路由全部由配置决定。

现阶段未提供 VICIdial、天润、七陌的独立媒体 provider：没有确认公开接口足以把通话原始双向音频接入本项目。VICIdial 所使用的 Asterisk 或其他系统提供的标准 SIP 中继，可以使用已实现的 PBX provider。仅有“发起呼叫”接口不能代替媒体接入。

配置保存在现有受限权限 SQLite 中。回读仅返回凭据是否设置；不写入文字历史或浏览器持久存储。旧版本配置默认不启用电话功能。保存过程中留空凭据保持已保存值，明确清除才删除。

协议测试使用本地可控服务器，不拨打真实号码。实体 PBX、运营商中继、云应用授权及手机端播放延迟需要在甲方选型后实测，测试通过不代表真实线路已验收。

## 接入与启动

1. 在对话配置选择咨询或销售，填写其资料／要求；按所选语音模式准备三模型或只准备 LLM。
2. 在电话接入选择 provider、填写参数。按照 [Asterisk](telephony-asterisk.md)、[FreeSWITCH](telephony-freeswitch.md) 或 [云平台](telephony-cloud.md) 完成线路和应用侧准备。
3. 接听需总开关与 `inbound_enabled` 同时启用，再将号码路由到专属应用；外呼仅需总开关，保留手动开始。
4. 来电自动接纳后进入通话；外呼切换到外呼视图、填写号码后手动发起。拨号接受不等于接听，云路由回调也不表示媒体已就绪。
5. 在历史按来电／外呼方向、主被叫号码、模式和 provider 识别本通；云文字等待正式回执导入。

公共电话媒体接口为 `MediaDriver`，语音业务复用 [Pipecat 电话 transport](telephony-transport.md)。云模式则使用受认证的模型网关和官方回执。单通失败不自动重拨；服务正常退出会结束当前通话。强杀进程无法保证远端 PBX／云电话已挂断，重启只会把本机未结束历史标记为失败，因此部署侧也应设置供应商通话超时。

电话凭据、模型网关鉴权码和回执鉴权码独立保存。对外只开放云 provider 文档里的几个认证 HTTPS 入口，管理 API 留在本机／管理网。硬件媒体保持受信任网络配置，具体传输限制由所选 provider 文档说明。
