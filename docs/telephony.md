# 电话外呼 provider

电话接入与网页语音共用销售配置和单会话限制。四组 provider 全部默认关闭；配置读取、保存和应用启动都不会连接 PBX、云平台或发起电话。只有操作员启用选定 provider 并明确提交被叫号码，才开始手动外呼。

| Provider | 模式 | 适用线路与设备 | 前置条件 |
| --- | --- | --- | --- |
| Asterisk | 自带语音模型 | 运营商 SIP 中继、通过 SIP 接入的 FXO／E1／VoLTE SIM 网关 | ARI、原生双向 WebSocket 媒体、PJSIP 线路 |
| FreeSWITCH | 自带语音模型 | 运营商 SIP 中继、通过 SIP 接入的 FXO／E1／VoLTE SIM 网关 | ESL、原生 UDP unicast、SIP gateway |
| 阿里云智能联络中心 AICCS | 平台托管语音 | 平台审核和开通的外呼线路 | 云应用、外呼号码、可访问的 LLM 网关与事件回调 |
| 腾讯云联络中心 TCCC | 平台托管语音 | 平台审核和开通的外呼线路 | 联络中心应用、外呼号码、自有 LLM 接口与事件回调 |

硬件的模拟／数字／蜂窝接口由网关转换成 SIP，应用在 PBX 层接入，避免按品牌重复实现同一协议。SIM 网关必须支持甲方所选运营商的 VoLTE 语音和线路规则；只有数据连接的 4G 模块不能据此当作语音网关。设备型号、号码和中继路由全部由配置决定。

现阶段未提供 VICIdial、天润、七陌的独立媒体 provider：没有确认公开接口足以把通话原始双向音频接入本项目。VICIdial 所使用的 Asterisk 或其他系统提供的标准 SIP 中继，可以使用已实现的 PBX provider。仅有“发起呼叫”接口不能代替媒体接入。

配置保存在现有受限权限 SQLite 中。回读仅返回凭据是否设置；不写入文字历史或浏览器持久存储。旧版本配置默认不启用电话功能。保存过程中留空凭据保持已保存值，明确清除才删除。

协议测试使用本地可控服务器，不拨打真实号码。实体 PBX、运营商中继、云应用授权及手机端播放延迟需要在甲方选型后实测，测试通过不代表真实线路已验收。
