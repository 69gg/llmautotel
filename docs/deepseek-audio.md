# DeepSeek 语音接入

协议核对日期：2026-11-14。ASR 和 TTS 各自选择 `protocol=deepseek`，填写独立的根地址和密钥。官方根地址为 `https://api.deepseek.com/v1`，需保留 `/v1`；不填写完整工具路径，不自动复用文本模型密钥。两种语音工具均不需要模型名称，旧模型字段仍保存但不发送。

## 分段识别

`POST {base_url}/tools/asr` 使用 multipart，仅包含 `file` 字段。复用 Pipecat 分段 WAV：16 kHz、16 位单声道 PCM，读取响应 `text`。本机在上传前拒绝超过 8 MiB 或 120 秒的片段。语种由服务自动识别，不发送 `model/language`。

官方明确不支持流式识别，因此仍是用户停口后上传一段音频；空结果恢复倾听，不生成用户消息。不能因更换此 provider 就宣称已经接入实时 ASR 或达到总响应 1 秒。

## 双向流式合成（默认）

选择 `protocol=deepseek` 后，`tts.streaming_input=true` 默认开启 WebSocket 双向流：根地址自动转为 `ws/wss` 并追加 `/tools/tts?format=pcm`，填写音色时再加 `voice_id`。密钥只通过 Bearer 请求头发送，不放进 URL。LLM 每段文字立即发送 `text` 事件，同时读取二进制 PCM，不等待完整句子或整轮生成结束。

复用 Pipecat 1.12.0 的 TOKEN 聚合与音频序列队列，中文句段独立连接：完整句末发 `finish_text`；首段低延迟模式还可在达到最少字数的中文逗号／分号结束。后续按中文整句，不拆金额小数、型号或英文单词。英文等无中文句界的文本在本轮结束时确认，不承诺逐字或英文逐句对齐。固定欢迎语、工具挽留与告别保持一个完整检查点。

只有收到 `finish/code=success` 且非空、采样完整的音频，才把该句文字排在音频之后提交；实际播放完成仍由传输队列确认。缺少结束确认、错误事件、超时或截断按失败结束会话，不把未播完草稿当作已说。首个音频块的到达不代表整句已播放。

打断先撤销旧连接的回合所有权、清空音频队列并取消接收任务，再异步关闭连接。新回合使用新连接，迟到的连接或 PCM 不能恢复旧输出；连接取消、挂断及失败均释放资源。单连接按全部字符保守限制到 10,000 字符及 64 KiB，不自动续传。

## HTTP 合成（兼容选项）

设置 `tts.streaming_input=false` 使用 HTTP 分句路径，保留旧服务接法。其他音频协议忽略此开关，不改变原请求。

`POST {base_url}/tools/tts` 发送 `text`、`format=pcm`，填写音色时发送 `voice_id`。音色为 `stella` 或 `tide`，留空由服务选择。音频响应边合成边返回，为 24 kHz、16 位小端、单声道 PCM；其他采样率会被拒绝。

不发送模型名、语言、语速或 `instructions`，旧语气配置保留供切回其他协议使用。音频字节跨请求块对齐；空输出、截断、错误响应或末尾半个采样均按合成失败处理，不把未完成文本记为已播放。取消时释放请求，不尝试续传。

## 协议验证

自动化使用真实 loopback WebSocket 服务验证多次文字输入、未生成完就到达音频、按句完成确认、采样对齐、中文金额边界、迟到连接、连续打断、告别检查点、合成中挂断和无响应超时；使用可控 HTTP 服务验证完整地址、鉴权、仅文件上传、自动语种、无模型字段、两个音色和默认音色、PCM 对齐与采样率、失败去敏和独立配置持久化。真实账户和设备效果单独验收，不以协议测试代替延迟验收。

本轮真实账户复测：WebSocket TTS、HTTP TTS 和 ASR 均返回 HTTP 402，未获得成功语音样本。ASR 使用静音 WAV 仅探测协议／账户响应，不作为识别效果验证；未修改正式配置。完整结果和待验证范围见 [验收记录](acceptance.md)。

同日稍后在新服务器使用用户最后提供的新 Key 做临时内存测试，WebSocket TTS 和 ASR 均成功，并完成一轮真实语音管线。停口至有效语音 3377.9 ms，未达到 1 秒目标；没有替换正式配置或重测 HTTP 回退路径。单项耗时、同音字差异、费用观察和样本限制见 [新服务器测量](latency.md#新服务器与临时-deepseek-key-实测)。
