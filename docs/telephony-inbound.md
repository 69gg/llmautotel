# 来电咨询与 SIP／云通信接入

来电接入优先于外呼展示；旧销售外呼和浏览器语音仍保留。默认对话模式为 `consultation`，四个电话 provider 的 `enabled` 总开关和 `inbound_enabled` 接听开关均为 `false`。不启用时不连接 PBX、不调用云电话控制接口，也不接纳回调创建会话。

## 选择线路

| 甲方提供的能力 | 选用 provider | 音频流向 |
| --- | --- | --- |
| 标准 SIP 中继、VoIP 线路、通过 SIP 接入的硬件网关 | Asterisk 或 FreeSWITCH | 运营商／供应商 SIP → PBX → 双向 PCM → 本机 ASR／LLM／TTS |
| 阿里 AICCS 通信智能引擎大模型应用呼入 | aliyun | 平台接听与 ASR／TTS → 认证本机 LLM 网关 |
| 腾讯云客服 TCCC 来电 AI 智能体 | tencent | 平台动态来电路由与 ASR／TTS → 认证本机 LLM 网关 |

阿里 AICCS 适配不代表任意阿里 CCC 产品都支持同一接口。其他供应商提供标准 SIP 时可走 PBX；只有呼叫控制 API、没有原始双向媒体或自定义模型网关，不能据此适配为完整语音 provider。应用不实现自行向运营商注册的裸 SIP 栈，复用 PBX 的中继、号码路由和编解码。

## 咨询配置

`conversation.mode` 可选择 `consultation` 或 `sales`。咨询配置为 `consultation.product_info`、`instructions`、`opening`；销售原有 `sales.goal`、`product_info`、`instructions`、`opening` 不变。它们独立保存，方向与模式相互独立；例如来电也可显式选销售，外呼也可选择咨询。

默认咨询先简短欢迎，再以最新用户发言为当前问题，依据产品资料介绍功能、使用方法和价格。资料没有的事实明确说明无法确认；可以澄清回答当前问题必需的信息，不主动调查用途，也不把回答强行转成购买意向。不承诺没有实际工具支持的订单、退款、预约或转人工。

咨询模式不提供 `retain_once`。拒绝购买或暂时不用某项功能，不意味着结束咨询；明确要求结束或明确表示咨询已结束时才告别，包含祝福。原生语音等待告别播放检查点后挂断，插话可取消旧告别挂断。云平台执行自己的打断、播放和结束行为，其能力限制见 [云平台接入](telephony-cloud.md)。销售模式的直接推销、一次挽留和工具状态完整保留。

首次读取旧版无 `conversation` 的保存配置时，默认切为咨询，复制原产品资料，保留完整销售组；不复制推销要求或旧销售开场。保存后新分组持久化。旧历史不迁移内容；缺少模式的旧历史仍标为销售，缺少方向的旧电话视为外呼。

## 原生 SIP 入呼

1. 在 PBX 开通和测试甲方 SIP 中继／VoIP 线路，并配置接收的号码。甲方账号、线路及 PBX 由甲方提供。
2. 完成本机咨询资料及 ASR、LLM、TTS 配置。
3. 选择 Asterisk 或 FreeSWITCH，填写原生入呼参数。入呼不要求外呼拨号模板、网关名或主叫号码。
4. 在 PBX dialplan 中将目标号码送入本应用的专属入呼路由。Asterisk 使用独立 `incoming_app` 和 `inbound_marker`；FreeSWITCH 使用专属变量标记的入呼 `park`。具体配置见 [Asterisk](telephony-asterisk.md) 与 [FreeSWITCH](telephony-freeswitch.md)。
5. 显式勾选总开关及接听开关并保存。后台建立事件连接，工作台显示监听状态；没有页面也可接听，关闭网页不挂断电话。

号码白名单 `inbound_numbers` 为字符串数组；原生留空表示接受专属路由上的所有来电，非本应用路由不会接管。事件只接管已存在通道，先争用本机单会话槽，再接听与初始化媒体，不创建新被叫通道。外呼和媒体通道不会被误当作入呼。第二通来电忙线拒接，不创建伪历史。

Asterisk 独占入呼应用的 ARI 事件连接，并向单通媒体驱动分发事件，避免另一 WebSocket 抢走同应用控制权。FreeSWITCH 用入呼 UUID 接听并复用原生 UDP 媒体。断连后监听器重连，不查询并重接旧通话；既有单通会因媒体或事件失效结束。连接参数改变时，当前来电使用快照收尾，之后才更换监听。关闭接听阻止新接纳，已接通通话不被配置保存强制挂断。

## 云平台原生入呼

回调入口是 `POST /api/telephony/aliyun/inbound` 和 `POST /api/telephony/tencent/inbound`，与最终文字回执 `/events` 独立。完成 [云文档](telephony-cloud.md) 中的正式控制台配置，不需要调用本机外呼开始接口。

- 阿里：号码绑定到 AICCS 大模型应用，配置开场变量回调及 UID 签名校验；本机返回 `bizParam.call_id` 绑定模型会话。已鉴权且启用时遇忙线，调用官方 `HangupOperate`，没有自造“拒接 JSON”。关闭本机接入后不调用 SDK，云控制台必须同步关闭或改好兜底路由。
- 腾讯：配置正式 `callInBound` 动态路由、预配置来电 AI 智能体；本机返回 `OverrideAIAgentId` 和官方提示词变量，绑定模型会话。忙线返回空 `CallInBound`，由平台拒接。腾讯静态兜底路由须按甲方业务设置，不能把接口超时当作已接纳。

云平台的应用号与被叫号码白名单必须匹配，网关及回调各使用独立秘密。回调重试按 provider 和远端通话 ID 返回原会话，不重复创建或接听；已结束通话也不因重试复活。模型请求只能使用已接纳的本通标识，新生成请求使旧流失效。正式文字回执可在挂断后更新已有历史。

## 工作台与生命周期

`GET /api/telephony/inbound` 只返回接听状态，不做探测拨号：

| state | 含义 |
| --- | --- |
| disabled | 总开关或接听开关关闭 |
| incomplete | 资料、模型或入呼参数缺失 |
| connecting | 原生监听正在建立 |
| listening | 原生事件连接已建立，可接收专属路由事件 |
| failed | 原生连接失败或中断，按配置重连 |
| pending | 当前来电结束后再更新线路连接 |
| awaiting_callback | 云入呼参数已配置，等待认证回调；不表示云账号／线路已通过健康检查 |

网页、外呼、四种来电都竞争同一槽位。来电记录包含 `direction=inbound`、主叫 `caller`、被叫 `destination` 和远端 `remote_id`，不含密钥或录音。接纳后立即挂断、尚未启动媒体时也会回收原来电通道；收尾结束前不释放槽位。单通失败不自动重拨或重接。

公网反向代理仅开放已认证的云模型、入呼及最终回执入口；配置、控制、历史、状态和 WebRTC 留在本机或管理网。回调地址的秘密查询参数不要记录在代理访问日志里。当前没有账号系统，也没有排队、转人工或多坐席并发；忙线策略明确是拒接第二通。

## 验证边界

协议与生命周期测试使用可控 HTTP、WebSocket、TCP 和 UDP 验证实际请求、接听现有通道、不外呼、忙线、重试、快照、提前挂断和默认关闭。实体 PBX、云应用账号、运营商号码、真实入呼欢迎播放、云控制台变量注入、回声／插话以及手机端停音延迟，仍需要甲方线路验收。详见 [验收记录](acceptance.md)。
