# 语音工作台前端

React、TypeScript 与 Vite 实现，使用 pnpm；依赖版本由 `package.json` 和 `pnpm-lock.yaml` 固定。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

开发服务默认只监听本机。`/api` 代理到本机后端 `http://127.0.0.1:8765`，可复制 `.env.example` 到 `.env.local`，通过 `LLMAUTOTEL_API_URL` 修改代理目标。供应商密钥只能在配置页面输入，不要放进前端环境变量。REST 请求默认在 10 秒后中止，可通过 `VITE_API_TIMEOUT_MS` 调整；创建通话超时意味着未确认服务器是否收到请求，后端会对未协商成功的会话槽位执行超时释放。

```sh
pnpm build
pnpm test
```

`build` 同时执行 TypeScript 检查和生产构建。测试覆盖配置保存、保留/清除密钥、保存失败恢复、API 错误提示及语音生命周期。

配置回读只包含密钥是否存在；空密钥输入在保存时省略，显式清除使用 `null`。成功保存后清空密钥输入，不使用浏览器持久存储。

ASR 和 TTS 可以独立选择“OpenAI 兼容”或“小米 MiMo”接口协议。切换协议仅改变请求格式，不修改已经填写的 API 地址、模型、音色或密钥；地址、模型和音色按服务商文档填写。MiMo 识别语言使用其支持的 `auto`、`zh` 或 `en`。

文本模型可选择启用/关闭思考及推理强度（无、低、中、高、最高）。两个选项默认均为“服务默认”，对应配置 `null`，后端不向模型请求发送这些可选参数；显式选择后才发送，按所选模型支持范围设置。DeepSeek 当前支持 `none`、`low`、`high`、`max`，兼容配置 `medium` 时后端映射为 `high`。现有配置及每通会话的配置快照保留这些选项。

语音使用 Pipecat Client 1.13.1 和 SmallWebRTC Transport 1.10.8。通过官方 `mediaManager` 扩展接口注入薄本机适配器，使用浏览器 `getUserMedia` 获取麦克风、音轨 `enabled` 控制静音，Web Audio 读取即时 RMS 音量。它不录音或导出 WAV，不实例化 SDK 默认的 Daily 设备管理器，因此不加载其外部设备脚本或遥测。没有默认 STUN/TURN 或第三方音视频平台；网络目的地为本机后端，以及后端按配置访问的三个模型服务。

先请求麦克风权限、开启浏览器回声消除，再创建服务端会话并协商 WebRTC。通话在切换导航时继续；修改配置只影响下次通话。挂断、连接失败或卸载工作台均停止音轨、关闭音量分析上下文、清除播放源并结束服务端会话。旧连接迟到的回调不能重新播放或改变下一通状态。

首次明确拒绝配置目标行动时，AI 在服务端直接说明价值、温和挽留一次并保持通话；再次明确拒绝或直接要求结束时，调用服务端挂断工具。常规话术围绕所配置目标询问意向，不调查用户用途或场景；购买、订阅等目标使用相同前端。挽留被打断也不重复；含糊回应继续交流，不弹出挂断确认。服务端完整播放带祝福的结束回复后通过 RTVI `server-message` 发出 `{ type: 'call-ended', reason: 'ai_hangup' }`，前端标记当前通话正在正常结束，等 WebRTC 断开后再清除播放源、释放设备并查询最终记录，避免截断告别尾音或把正常结束显示为连接异常。前端结束 REST 请求仍使用 `connection_lost` 收尾，由服务端保留已确定的 `ai_hangup` 原因，历史页显示“AI 确认结束”。重复消息不会重复清理；未知原因和旧连接消息不改变当前通话的结束判断。

对话文字只来自服务端已输出记录；完整播放的文字会保留，打断前生成的内容由后端作为下一轮内部系统背景，不会展示为已说内容。内部标签在 TTS 与记录之前过滤，网页无需通过隐藏文本来掩盖语音泄漏；旧历史保持原样。本地与远端音量均分析真实音轨，不保留分析样本。浏览器限制自动播放时可点击“播放声音”。语音需要本机地址或 HTTPS 的安全上下文。

SmallWebRTC 1.10.8 的远端 `onTrackStarted` 回调仅传入音轨，参与者参数可以省略；网页仍须将该音轨挂到音频元素、调用播放并启动音量分析。本机麦克风适配器明确传入 `local: true`，本地音轨不会进入扬声器播放。回归测试覆盖这份实际回调格式、自动播放受限提示和挂断清理，不能以服务端文字记录代替浏览器播放验证。

历史页从服务端读取通话列表、文字详情及通话开始时的配置快照，显示时间、目标、结束原因和被打断标记。删除前可以取消，活动通话禁止删除；后端删除失败时保留记录并允许刷新。切换详情会取消上一份请求，迟到响应不能覆盖当前选择。

默认打开“电话接入”的来电接听监控，保留手动外呼切换与浏览器语音入口。Asterisk、FreeSWITCH、阿里 AICCS 和腾讯 TCCC 的独立表单来自 `/api/telephony/providers`，支持布尔接听开关、号码字符串数组、数字范围及凭据。所有总开关与接听开关默认关闭；显式启用接听并保存后原生后台建立连接，云等待认证回调。只有手动点击发起才拨号。咨询／销售资料独立保存，切换不删除；新来电显示主被叫号码、方向、模式和记录，工作台操作见 [来电工作台](../docs/frontend.md)。

Asterisk／FreeSWITCH 沿用现有 ASR、LLM、TTS，阿里云／腾讯云方案由平台托管语音并调用已配置 LLM。页面按所选方案检查目标和所需模型配置，但真实线路、PBX、平台企业资质与云侧配置由供应商接入文档确定。接口调用成功不代表实体线路验收。

电话页通过 REST 查询活动会话，并按一秒间隔串行轮询当前状态和文字，不访问浏览器麦克风或播放本机音频。媒体方案显示实时文字；云平台文字仅在官方记录或回执到达后更新，不能承诺接通后立即实时显示。振铃、接听、倾听、识别、思考、说话和结束状态来自服务端；同一时间浏览器语音与电话共用一通会话槽位。另一个标签页抢先开始时显示服务端 409 错误。切换页面只取消轮询，远端电话继续；返回页面会恢复查询。手动“挂断电话”使用共享结束接口，卸载页面不会隐式挂远端电话。

电话凭据留空保留已有值，清除发送 `null`，成功保存清空输入；全部 `*_set` 回读标记从 PUT 请求移除。普通对话配置保存也保留电话参数，不将凭据写入浏览器持久存储。通话记录统一显示浏览器／电话来源；电话详情另外显示 provider、被叫号码和忙线、未接听等结束原因。

前端自动化使用可控客户端验证拒绝授权、连接失败、两标签竞争返回、生成中挂断、迟到响应、旧回调隔离、麦克风释放、导航保留及资料缺失禁用开始。AI 挂断回归覆盖告别尾音期间保留播放、断连后释放资源、服务端最终记录、重复/未知/旧连接结束消息和正常关闭不显示异常。配置测试覆盖协议独立选择、保留连接参数和思考选项提交/重置。历史测试使用与服务端相同的记录结构，覆盖展示、AI 确认结束、删除/取消、活动记录与 409、加载错误、重试和详情切换竞态。MiMo / DeepSeek 已完成真实接口连通性验证，真实设备通话仍待验收，详见 `../docs/acceptance.md`。

新增电话页测试覆盖默认禁用与无自动拨号、元数据字段、跨 provider 凭据保留／清除、配置失败重试、保存后的启用状态、手动开始／挂断、浏览器占用、409 竞争、云托管与本机语音的配置差异、轮询卸载清理及电话历史来源。测试使用可控 API 替身，未拨真实号码；真实供应商和电话设备验收仍需单独记录。
