# OpenI 语音延迟原型（实验）

TTS 候选任务使用 `tts_autotest.py`：在同一 GPU 以相同参考音、文本与输出采样率重跑 Qwen3、CosyVoice3 和必要时的 VoxCPM1.5，并分别记录加载预热、有效首音、RTF 及播放队列断粮。vLLM 替换 Torch，必须使用不继承系统 site-packages 的环境，避免加载旧 FlashAttention CUDA 扩展；按完整 `requirements-cosy-vllm.lock` 安装，包括 Torch/CUDA，禁止运行时重新解析依赖。该锁由 worker 输入加 vLLM 0.9.0，并通过独立 overrides 将 Torch/torchaudio 固定为 2.7.0 后生成。Vox 与镜像共用 Torch 2.6，按 `requirements-voxcpm.lock` 重放全部非 CUDA 依赖，安装前后检查 Torch、torchaudio 版本和真实 CUDA 运算，避免重复下载整套 CUDA。准备失败只记失败，不当作模型慢。`--vllm-only` 与 `--vox-only` 分别补测候选和配对 Qwen 基线，不重复其他候选；二者互斥。下载、编译、推理仅在 GPU，准备阶段超时 7200 秒；有进度的下载不因短时无日志而中断。

依赖下载另设 `UV_HTTP_TIMEOUT=600`、`UV_HTTP_RETRIES=5`、`UV_CONCURRENT_DOWNLOADS=4`，避免只延长父进程却仍沿用下载器的默认短超时；显式传入的同名环境变量优先。此项只改善环境准备可靠性，不计作模型推理提速。

OpenI 启动文件 `tts_vox_autotest.py` 对应 `--vox-only`，`tts_vllm_autotest.py` 对应 `--vllm-only`。二者均需与同目录的依赖锁及原缓存镜像配套上传，不单独拷贝入口文件。

常驻服务模板 `settings.service.json` 启用 `service_tts_first_audio_priority`：每段 TTS 首个非空 PCM 生成前暂停 LLM 的后续 token 解码，首块交付前恢复；可关闭作同链路对照。取消、超时、异常和无输出均释放等待，不改变打断、上下文或挂断规则。该策略只调度后续解码，不能抢占已提交的 GPU 算子。服务需更新代码并重启；测量仍以停口到有效音频为准。

2026-11-15 首音优化已部署到常驻任务935318，业务服务器同步并重启。正式业务三轮有效首音1423.3/1244.7/1413.3ms，中位较上一版降低32.2%，仍未达到1秒。TTS分项中位583.7ms不等于完整链路或设备播放。534项后端测试通过、3跳过；逐轮数据见[首音优化报告](results/2026-11-15-first-audio-priority.json)。

独立于正式语音应用，验证一张 NVIDIA GPU 同机运行 ASR、文本 LLM 和 TTS 或原生 Omni 语音模型的延迟，使用 OpenI 官方在线推理代理传输 WebSocket，不使用隧道或端口穿透，不修改正式配置、历史和线路。已测配置包括 `settings.station.json` 的 SenseVoiceSmall、Qwen3-1.7B 和 CosyVoice3，以及 `settings.omni.json` 的 MiniCPM-o 4.5；原来的流式 Paraformer 与 Qwen3-4B 配置保留在 `settings.json`。源代码与 Python 依赖均锁定版本。

这是选型原型，尚未接正式 Pipecat 管线、真实 VAD、电话、浏览器音频与连续对话。问题为内存中生成的合成语音，产品资料为虚构测试资料。这里的通过不等于正式通话验收。

## 运行

### Omni 独立实验

`settings.omni.json` 使用 MiniCPM-o 4.5 原生半双工流式语音，复用本实验的认证网关、实时输入和内存播放计时，不替换正式 provider。创建在线推理时只挂载站内 `dang/MiniCPM-o-4.5`，沿用已经验证的 A100 40GB 镜像。`prepare_omni.py` 保持站内权重只读，在独立目录组合主权重、校验过的源码包与语音组件；不下载主模型分片。

`minicpm-o45-source.tar.gz` 包含锁定模型提交的配置、远程代码、分词器、官方助手参考音频、Apache-2.0 许可证与逐文件散列清单；配置固定来源修订与包散列。五个 Token2wav 文件约 1.23 GB，优先从 ModelScope 国内镜像分块下载，网络错误自动回退 hf-mirror；两个来源均锁定修订并使用同一组大小和 SHA-256 校验。已完成文件校验后复用，未完成文件保留 `.partial` 并通过 HTTP Range 断点续传；响应范围必须精确匹配，镜像忽略 Range 时从头写入，避免错误拼接。每 15 秒打印文件进度，不输出签名重定向地址。整体准备限时 7200 秒，客户端 `wait` 默认等待 10800 秒（可用 `--prepare-timeout-seconds` 调整），网关有效期 14400 秒；不会因为几分钟下载慢而停止任务。镜像 Torch/CUDA 经运算验证后复用，其余依赖锁在 `requirements-omni.lock`。这轮使用 SDPA、关闭思考、仅加载语音相关模块，不启用视觉。

从模板生成 `settings.run.json` 并填入本机测试令牌的 SHA-256 后，使用同一组 `probe/load/wait/local/remote` 命令；先以 `--repeats 1` 各测三题。输入保持 16 kHz、20 ms PCM 块，模型在讲话期间每整秒预填一次，停口后尾块补零到一秒并封口。报告记录补零长度、最终预填、首段文字、首 PCM、有效首音和生成总耗时。模型直接理解音频，`user_text` 为空，不伪造独立 ASR 转写；预期问题另记。问题由同模型强制朗读生成，仅存内存，属于预热且存在合成语音偏差。端点继续是 200 ms 模拟等待，不能代替真实 VAD/电话验收。

Omni 的文字随语音块一起交付，`first_delivered_text_after_end_ms` 不等于内部首文字 token。原生语音块为约一秒，首包和有效首音分别统计。输入边界、资产完整性自动化测试不证明 GPU 性能；实际结果另行记录。任务有效期和推理超时都不负责停止 GPU 计费，实验后仍需在平台停止并确认终态。

任务 934993 已完成五个语音组件的大小及 SHA-256 校验，依赖也已安装。首次初始化参考音色时，minicpmo-utils 1.0.5 的 set_stream_cache 未像后续 stream 一样启用自动混合精度，FP32 说话人向量进入 FP16 线性层后报 dtype 不匹配；该次没有推理样本。适配层为缓存初始化补齐受 omni_tts_fp16 控制的 CUDA autocast。准备环境和已验证资产另存缓存镜像，重建时重新绑定站内主权重；只更新私有符号链接，遇到同名普通文件立即失败，不覆盖权重。随后任务 935021 已验证缓存镜像重建、修复后的 GPU 初始化和六轮有效语音，详见[实际结果](#2026-11-15-omni-原生流式结果)。

### 全站内模型基线

`settings.station.json` 使用站内 `SenseVoiceSmall`、`Qwen3-1.7B`、`Fun-CosyVoice3-0.5B-2512` 三个模型，保留原来的流式 Paraformer 配置。创建任务时选择三个预训练模型，并由此配置生成 `settings.run.json`。所有权重来自 `c2net.prepare()` 返回的站内路径，不依赖镜像的用户缓存，不回退外网下载。

这组 ASR 是整句识别，输入音频继续实时传输，但仅在停口后识别整段；LLM 和 TTS 继续流式输出。`asr_streaming` 默认 `true`，设为 `false` 时使用整句模式；`asr_generate_options` 可配置语言等模型识别参数。报告记录实际模式，不能将整句识别结果写成流式 ASR 的验收。识别输出的语言、情绪等特殊标记不会进入 LLM 的用户文本。

## 计时与局限

输入按 16kHz、单声道 int16 PCM、20ms 块实时发送。ASR 在用户讲话期间处理流，模拟停口等待默认 200ms，再最终识别、生成回复。LLM 的文本迭代器直接输入 CosyVoice 双流路径，音频边产生边返回。

口径为最后一个有效输入块的计划播放结束时刻，到内存终端播放队列中首段有效输出声音。输入尾部静音剔除，输出前导静音和包间等待计入；20ms RMS 窗口阈值为100，报告首包与有效音频的区别。local 测 OpenI 同机内存终端，remote 包含官方代理网络及播放队列。报告保留识别和回复，需核对语义是否有效；少量样本的 p50/p95 仅描述本次数据，不代表稳定承诺。

合成问题会预热 TTS，所以首轮回复不能称为完整冷启动。依赖、下载、模型加载的启动耗时与已加载后的响应分开记录。不保存输入或输出录音。生产回声消除、真实停口检测、耳机/外放、并发及打断未由本实验验收。

取消使用生成代次过滤迟到音频，但这是实验级机制，不替换正式应用的打断保障。HTTP 状态接口和 WebSocket 控制指令需要认证；健康接口只返回阶段，不返回日志或模型资料。

## TTS 优化与接口对照

`settings.compare.json` 复用站内三模型，增加配置文本与逐轮分块对照，默认开启 `tts_reset_hop`。CosyVoice 当前源码把逐渐增大的 `token_hop_len` 保存在模型实例上；此选项在每段合成开始恢复模型原始值，保留训练要求的块长，不修改上游文件。旧配置默认不复位，可使用同一任务比较。

## 低延迟对照矩阵（隔离实验）

`settings.optimizations.json` 保留原基线，顺序对照：真实裁剪输出前导静音、内存中适配实际文字/PCM 块、100 ms 模拟端点、停口即时预生成、资料快照隔离的完整回复语音缓存、LLM 和声码器实际流式 `forward_chunk` 编译、编译与预生成组合。使用相同合成问题并逐条保存输出文字；不修改正式产品配置或代码路径。

预生成以已知输入音频结束作为触发点，确认后才开放播放，属于理想端点的收益上界，不能冒充真实 VAD 预测。另测取消候选、恢复官方 speculative snapshot、追加新音频并回复，检查 KV 长度和丢弃候选音频。缓存只有模型完整答案精确匹配批准文本才命中；未知答案或价格、音色、提示词快照变化不得复用。缓存准备、编译和预热时间单列，异常如实记录，不把失败或占位话记成达标。

运行 `client.py --mode optimize --repeats 1`；选定方案后可用 `--variant NAME --mode remote` 从媒体服务器复测。所有 GPU 编译、权重和推理仅在 OpenI，本地只运行 `tests/test_openi_optimization.py` 等轻量验证。每批结束通过平台停止任务并核实 STOPPED；没有设备播放或真实 VAD 验收前，结果仅为内存播放口径。

首次矩阵初始化中，Torch `inference_mode` 装饰器使 `getsource()` 返回原方法、`__globals__` 却仍属于装饰器模块，动态方法绑定报 `NameError: torch`。现同时通过 `inspect.unwrap()` 获取源码和命名空间，并补充外部装饰器命名空间回归测试；失败任务不计入延迟样本。

## GPU 整条业务管线（新版）

`voice.pipeline=gpu` 把原 Pipecat 业务管线移到常驻 GPU 进程：16kHz 单声道 PCM 经一条鉴权 WebSocket 进入，VAD、ASR、上下文、LLM、分句与 TTS 在 GPU 端衔接。三模型直接调用内存适配层，不再经业务服务器分别发起 HTTP 请求。业务服务器保留网页/电话入口、输出队列与历史落库。`local` 保留原独立 API 编排，不自动故障回退。

配置页的“处理链路”可切换；GPU 模式使用文本模型根地址推导 `/realtime`，使用文本模型密钥鉴权。远端 `serve_realtime=true`，三模型名、24kHz PCM 和参考音色必须与服务匹配。新增 `requirements-realtime.lock` 固定 Pipecat 运行依赖，复用镜像模型栈，不下载新的 Torch/CUDA。快照去除全部模型密钥及电话线路凭据；GPU 不保存音频和对话。

GPU 按生成代次标注音频；插话后发出 flush，服务器清播放队列并丢弃过期音频。句子提交和挂断必须等服务器输出队列的 played 确认，过期确认不能恢复旧回复或执行挂断。保留现有咨询、销售、一次挽留和告别规则。单个 GPU 服务只允许一通实时会话，重复占用明确失败，断连释放任务和占用。

停口确认现在支持100ms，较短阈值可能拆开自然停顿，需要真实麦克风/电话验证。响应目标仍按停口到终端有效声音计时；不能将独立原型数据作为新版正式链路数据。业务服务器与 OpenI 模型服务器分别更新；当前账号只允许一个 GPU 在线任务，更新 GPU 时需安排模型加载中断窗口。常驻服务不自动到期关闭。

及 5 ms 令牌就绪轮询；不缩小训练分块来换首音。VoxCPM1.5 使用参考缓存和
官方 compile，输出以有状态重采样转换为 24 kHz。

`tts_autotest.py` 是不依赖交互终端的 OpenI GPU 测试入口：先测 Qwen 基线和
CosyVoice3，若优化后 CosyVoice3 未胜出才下载、测试 VoxCPM1.5。依赖与权重仅在
GPU 上从镜像安装；逐候选报告写标准输出及 `/tmp/output`，任务结束退出释放 GPU。
代码和无模型测试通过不能当作真实模型已通过，最终模型须以候选实测及上线后回归决定。

缓存镜像存在环境目录不代表依赖完整：首次自动任务的 Qwen 缺少
`faster-qwen3-tts`，CosyVoice 缺少 `wget`，这两项属于准备失败而非延迟样本。
测试入口现在先重放各自的完整锁文件（复用镜像 Torch/CUDA），再加载模型；
基线没有成功样本时禁止选出或发布所谓“最快模型”。
